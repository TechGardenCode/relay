# ND-34 — Session + attach polish deep-dive — painless-rollout bar

**Status:** resolved (2026-05-27)
**Affects:** `docs/prd/03-server.md` §5 (attach + reattach semantics) and §7 (session subcommands); `docs/arch/ws-protocol.md` (any frame additions for session naming or persona switch); `packages/server/src/attach/` (the `^D` detach gesture, the replay slice on reattach); `packages/server/src/cli/` (`relay session` subcommand surface).
**Surfaced by:** [[d-15-ux-rollout-posture]] resolution (2026-05-22). One of four per-surface deep-dives opened to gate Phase 1.5 rollout.

## Question
What is the minimum painless-rollout bar for **session and attach polish** — the moment-to-moment ergonomics of identifying, naming, attaching to, detaching from, and switching contexts within a Relay session? Today there are several known sharp edges (`^D` twice, blank-pane reattach on quiet sessions, UUID-only session identity, no persona switch without restart). Which of these must be smoothed before a non-author user can use Relay every day?

## Elaboration prompt
The inventory in [`docs/arch/ux-rollout-posture.md`](../arch/ux-rollout-posture.md) §5 lists what's painful today. The resolution must decide which items are P0, P1, or deferred-with-rationale.

**What to consider:**

- **(a) `^D` two-press detach per [[nd-25-relay-attach-detach-with-d-requires-two-keypresses-on-the-host-tty]].** Today detaching from `relay attach` requires `^D` twice on the host TTY. Standard terminal behavior is one `^D`. ND-25 is filed `open`; the root cause (raw-mode setup, canonical-mode drain, or control-sequence filtering inside `packages/server/src/attach/tty.ts`) is unclear. Decide whether ND-34 resolves by resolving ND-25 inline (single-press contract + code fix), by accepting two-press and documenting the gesture in user-facing docs, or by introducing a different detach key (e.g. the conventional `^B d` tmux-style chord). Note interaction with [[nd-30-relay-attach-stderr-event-stream-for-subprocess-of-attach-consumers]] — both touch `attach/tty.ts`.

- **(b) Replay catch-up for quiet sessions per [[nd-03-ring-buffer-size-for-attach-replay]] / [[d-g3-reattach-semantics]].** Today reattach sends a uniform 32 KB replay; a quiet session (no recent agent output) shows a blank pane until the agent emits new bytes. Decide whether the replay-on-reattach surface gains: (i) a "last-N-messages" mode (per-message rather than per-byte), (ii) a per-session-sized replay (longer for verbose sessions, shorter for quiet ones), (iii) a "show me the last response" shortcut backed by the transcript REST route ([[nd-04-transcript-pagination-api-shape]]), or (iv) no change with documentation calling out the limitation.

- **(c) `relay session show` surface alignment per [[nd-15-relay-session-show-subcommand-surface-alignment]].** ND-15 is filed `open`; PRD §7 enumerates only `list` and `kill` but the build-plan 6H ships `show`. Decide whether ND-34 resolves ND-15 inline (commit to the field set, output format, error behavior) or leaves it as an independent ND that 7D can pull in.

- **(d) `relay attach` raw-mode FSM variants per [[nd-17-relay-attach-raw-mode-tty-variant-of-the-5-1-client-fsm]].** ND-17 is filed `open`; pending per-keystroke streaming resolution (which has now landed as [[nd-24-per-keystroke-input-streaming-for-tui-agents]]). Decide whether ND-17 is now resolvable (claim the FSM is strict wire-correctness, or allow UX variants like collapsed Claimed state, timer-only Backoff) and whether ND-34 picks it up.

- **(e) Session naming / labeling beyond UUID.** Today sessions are identified by ULID (`01HXYZ...`). Decide whether sessions gain an optional human-readable label (`relay session start --name "auth-rewrite"`), how the label appears in `relay session list`, IDE tree view, and the status bar, and whether the label is unique per project. Storage implication: a column on `sessions` in [`docs/arch/sqlite-schema.md`](../arch/sqlite-schema.md) — file a migration if so.

- **(f) Persona switch without restart per [[d-g1-persona-application-semantics]].** D-G1 makes persona immutable for MVP; switching requires kill + restart. Decide whether ND-34 introduces a "switch persona" gesture (CLI + IDE) that does the kill + spawn-new-with-resume dance, surfacing the loss explicitly. Or honor D-G1's Phase 3 deferral and explicitly document "persona switch requires a fresh session" in the user-facing docs.

- **(g) `idle` status semantics per `docs/prd/01-conceptual-model.md`.** The spec defines `idle` as "reserved for a future agent-driven indicator" with no MVP transition. Decide whether ND-34 fills in idle (e.g. agent process alive but no output for N seconds → idle, resumes on output) or honors the punt and removes `idle` from the status enum entirely until a real use case exists.

- **(h) Attach distribution shape (overlap with ND-32).** Whether `relay attach` ships as its own package (`@relay/attach`) is also relevant here — it affects how third-party tools attach to sessions, which is a session-management consideration. Coordinate with [[nd-32-install-and-onboarding-deep-dive]] (a) so the decision lands in one place; the other ND references it.

- **(i) Detach-with-keep-session-running clarity.** Today `^D` (×2) detaches but the session keeps running. Decide whether the CLI prints an explicit "session 01HXYZ still running; attach again with `relay attach 01HXYZ`" line on detach, so the user is not left wondering whether they killed it.

- **(j) Multi-client claim handoff polish.** A user on device A holds the claim; device B tries to send; today the user on B sees the unstructured BUSY stderr line. The whole-claim-arbitration UX overlaps [[nd-33-ide-gui-overhaul-deep-dive]] (BUSY anchoring) and [[nd-30-relay-attach-stderr-event-stream-for-subprocess-of-attach-consumers]] (event stream). Decide whether the *CLI-side* of the handoff (when you are typing in `relay attach` and you get BUSY'd) needs polish too — clearer line, dismissal cadence, terminal-bell suppression — independent of the IDE story.

**Validation against the gate.** The resolution must end with a line of the shape "the painless-rollout bar for session + attach polish is: <one-paragraph statement>" so [[d-15-ux-rollout-posture]] §7 can quote it.

This is filed as `open` so the resolution lands as a deliberate deep-dive (Track 7D in `docs/build-plan.md`) rather than inline drift.

## Resolution

**Fix the one sharp edge that hits every attach on every device — make `^D` detach on a single press and confirm the session is still running — and resolve the doc-drift NDs inline; defer every feature-shaped item (session naming, persona switch, idle fill-in, CLI BUSY polish) as P1 with rationale, and honor the resolved replay contract unchanged.** The frame is the same as the sibling [[nd-32-install-and-onboarding-deep-dive]]: this deep-dive can ship cheap, source-install-independent levers now, and must name everything else as deferred-with-rationale rather than half-build it. For session + attach polish, exactly two things carry rollout weight and are cheap today: single-press `^D` (the most-cited moment-to-moment friction, repro'd in two e2e walks) and a detach confirmation so the operator isn't left wondering whether they killed the session. Everything else is either already-correct (replay), a doc gap that closes with a ratification (`session show`, the FSM variant), or a multi-surface feature whose absence the ND-33 sessions tree view already softens (naming).

### Per-item (a)–(j) triage

- **(a) `^D` two-press detach — P0, shipped. Resolves [[nd-25-relay-attach-detach-with-d-requires-two-keypresses-on-the-host-tty]] inline (single-press canonical).** Root cause: when `setRawMode` is silently no-op'd on the host, the first `^D` is a canonical-mode EOF delivered as a stdin `'end'` event, which the bridge didn't listen for. Fix: a defense-in-depth `stdin.on('end', () => client.close())` listener so single-press works whether or not raw mode took effect; the idempotent `client.close()` means the raw-mode `0x04`-in-`'data'` path is unaffected. Single-press is canonical (matches standard terminal EOF-on-empty-line + the already-documented §7 contract); the `^D`-overloads-EOF-to-agent cost is an accepted limitation in the same class as §5.1's "vim won't work." Rejected: documenting two-press as the contract, and a `~.`/`Ctrl-A d` escape sequence (discoverability burden + breaks shipped `^D` copy). Code: `attach/tty.ts` + `tty.test.ts`.

- **(b) Replay catch-up for quiet sessions — no change; honor [[nd-03-ring-buffer-size-for-attach-replay]] / [[d-g3-reattach-semantics]]. Does NOT reopen ND-03.** The 32 KB uniform replay is the resolved contract (§5.2: "viewport plus a Claude Code prompt-state worth of context"). Options (i) last-N-messages and (ii) per-session-sized replay would reopen ND-03's "no per-session knob" ruling for marginal benefit — explicitly declined. Post-[[nd-24-per-keystroke-input-streaming-for-tui-agents]] the blank-pane symptom is largely moot for the real agent surface: `claude`'s TUI redraws its frame on attach/resize, so a quiet session shows the last frame, not a blank pane. Option (iii) "show me the last response" is already reachable via the §2 transcript route ([[nd-04-transcript-pagination-api-shape]]); surfacing it as a one-key shortcut is P1, not rollout-blocking. Disposition: documentation (handbook Ch 5 already describes the short replay).

- **(c) `relay session show` surface alignment — P0 doc-alignment; resolves [[nd-15-relay-session-show-subcommand-surface-alignment]] inline.** 6H already shipped `show` against the exact field set ND-15 proposed (SQLite-direct read, `key: value` plaintext, exit-1 `No session with id <id>.` on miss). The §7 omission was the oversight. Ratified and propagated to PRD §7; no code change.

- **(d) `relay attach` raw-mode FSM variant — resolves [[nd-17-relay-attach-raw-mode-tty-variant-of-the-5-1-client-fsm]] inline (wire-correctness).** ND-24 didn't just clear ND-17's blocker, it dissolved the mismatch: per-keystroke streaming means the raw-mode client has no "draft" to commit, so the two unmappable §5.1 transitions don't exist on the CLI surface. §5.1 is a wire-correctness contract naming the IDE compose-field as one canonical UX without forbidding variants. The §5.1 rewrite ND-24 propagated already documents the `Idle → Claiming → Streaming → Idle` variant, so the standalone §5.1.1 footnote ND-17 proposed is redundant and not added. No runtime change.

- **(e) Session naming / labeling — P1, deferred with rationale. No migration ships.** A human-readable label is a genuine nicety but a multi-surface feature: it would touch `@relay/protocol` (session-create + session shape), `POST/GET /sessions`, a `0002_*` SQLite migration, the store repo, CLI `list`/`show` rendering, the extension tree view, and the status bar — a large fan-out for a cosmetic field. It is not on the critical path for daily non-author use, and [[nd-33-ide-gui-overhaul-deep-dive]]'s P0 sessions tree view already groups sessions by project and shows persona, which addresses most of the "which session is which" pain without a label column. Deferred until the tree view is in use and naming demonstrably remains a pain. (Because (e) does not ship, no `0002_*.sql` migration is created in 7D.)

- **(f) Persona switch without restart — honor [[d-g1-persona-application-semantics]]'s Phase 3 deferral.** No "switch persona" gesture ships. D-G1 makes persona immutable for MVP; switch = kill + start-fresh. Documented in the handbook as "persona switch requires a fresh session." This is the low-risk default the kickoff named, and it keeps the IDE GUI story ([[nd-33-ide-gui-overhaul-deep-dive]], which makes the same call) coherent.

- **(g) `idle` status semantics — honor the conceptual-model punt; neither fill in nor remove.** `idle` stays a reserved enum value with no MVP transition, exactly as `docs/prd/01-conceptual-model.md` already documents. Filling it in (an output-silence timer → idle) is speculative with no concrete consumer. Removing it would cost a status `CHECK`-constraint migration plus a `@relay/protocol` change and would contradict the running/idle/killed badge vocabulary [[nd-33-ide-gui-overhaul-deep-dive]]'s tree view references — churn for negative benefit. No change; the punt stands.

- **(h) Attach distribution shape — defers [[nd-29-distribute-relay-attach-as-a-standalone-package]] with a trigger.** [[nd-32-install-and-onboarding-deep-dive]] (e) handed this to 7D / ND-29; this resolution closes the loop by deferring ND-29: it is a third-party-integration concern, not a non-author-daily-use one, so it does not gate the rollout bar. `relay attach` stays bundled in `@relay/relay` per [[d-08-single-binary-vs-separate-packages]] (recipe-only, Option B). Re-open trigger: a constrained-distribution third-party consumer or a PWA native-helper companion.

- **(i) Detach-with-keep-session-running clarity — P0, shipped.** On a clean local detach the bridge now prints `\n[relay] detached from session <id>; the session is still running. Reattach with: relay attach <id>\n` to stderr. Gated on a `localDetach` latch set by the `^D`/`'end'` handlers — **not** on close code `1000` alone, because per `ws-protocol.md` §4.2 a `session_ended`-driven shutdown also closes 1000, and confirming "still running" then would misreport a dead session (the exact "did I kill it?" confusion this item removes). Code: `attach/tty.ts` + `tty.test.ts`. Pairs naturally with (a).

- **(j) Multi-client claim handoff polish (CLI side) — P1, deferred. No change.** The existing one-shot stderr line (`[relay] another device is interacting with this session.`) is adequate for the CLI surface; it emits no terminal bell, so there is nothing to suppress. Structured BUSY rendering is [[nd-30-relay-attach-stderr-event-stream-for-subprocess-of-attach-consumers]]'s job and the anchored-notice UX is [[nd-02-rejection-ux-for-busy-response]] / [[nd-33-ide-gui-overhaul-deep-dive]]. Over-polishing the CLI BUSY (dismissal cadence, bell suppression) is gold-plating for a single-user product where simultaneous multi-client typing is an edge case.

### Contract

1. **Two P0 code changes, both in `packages/server/src/attach/`.** (a) single-press `^D` via a `stdin.on('end')` defense-in-depth listener; (i) a `localDetach`-gated "still running / reattach with…" confirmation in the bridge's `onClose`. A `sessionId` getter on `AttachClient` lets the bridge name the session without re-threading the id. Both covered by `attach/tty.test.ts`.
2. **No close-code overload bug.** The detach confirmation fires only when the close was locally initiated (`code === 1000 && localDetach`); a `session_ended`-then-1000 close (§4.2) prints the session-ended line instead, never "still running."
3. **Three doc-drift NDs resolved inline.** [[nd-15-relay-session-show-subcommand-surface-alignment]] (ratify shipped `show` → PRD §7), [[nd-17-relay-attach-raw-mode-tty-variant-of-the-5-1-client-fsm]] (wire-correctness; §5.1 already carries the variant), [[nd-25-relay-attach-detach-with-d-requires-two-keypresses-on-the-host-tty]] (single-press, shipped with (a)).
4. **One ND deferred with a trigger.** [[nd-29-distribute-relay-attach-as-a-standalone-package]] — single-binary holds; revisit on a constrained-distribution consumer.
5. **No new schema, no new wire frames.** Session naming (e) is deferred, so no `0002_*` migration and no `@relay/protocol` change ship in 7D. The `idle` enum (g) is unchanged.
6. **Resolved contracts honored, not reopened.** [[nd-03-ring-buffer-size-for-attach-replay]] (32 KB uniform replay) and [[d-g1-persona-application-semantics]] (immutable persona) stand as-is.

**Why this and not "ship the naming feature too":** session naming is the most tempting P0 because ULID opacity is visible friction, but it is the single highest-fan-out item in the set (protocol + REST + migration + store + two client surfaces) and the ND-33 tree view already delivers project+persona grouping that covers most of the need. Shipping it here would couple a decision-first deep-dive to a multi-surface feature build and a schema migration for a cosmetic field — exactly the half-built-feature outcome the rollout-posture frame warns against. **Why this and not "decision-only, defer all code":** the `^D` two-press edge is the most-cited moment-to-moment friction in `docs/arch/ux-rollout-posture.md` §5, was reproduced in two e2e walks, and was flagged "worth fast-following before 6I" — deferring the cheapest, highest-leverage fix would leave a daily papercut in place for no reason. The chosen scope ships exactly the two levers a non-author feels on every session and names everything else as P1 or sibling-ND work.

**Surfaces new sub-questions:** none — (h) routes to the existing [[nd-29-distribute-relay-attach-as-a-standalone-package]] (now deferred) rather than opening a new entry.

**the painless-rollout bar for session + attach polish is: a non-author can detach and reattach without friction or doubt — a single `^D` cleanly detaches (raw-mode or canonical-mode host alike) and the CLI confirms the session is still running with the exact reattach command, so nobody fears they killed their work; `relay session show` is a ratified part of the CLI surface and the raw-mode attach FSM is documented as a wire-correctness variant of §5.1, closing the known doc gaps; the 32 KB reattach replay and immutable-persona contracts stand unchanged; and human-readable session naming, a mid-session persona-switch gesture, filling in the reserved `idle` status, CLI-side BUSY polish, and extracting `relay attach` as its own package are all deferred as P1 / sibling-ND work with documented rationale, none of them blocking daily non-author use.**
