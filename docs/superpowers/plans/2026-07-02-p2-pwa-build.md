# Relay PWA (Phase 2 MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up `packages/pwa/` and build the Phase-2 PWA MVP — a terminal-style Angular client over the canonical REST/WS contract — from the `docs/arch/pwa/` L0–L6 spec, implementing every MVP FR that does not gate on an open server ND.

**Architecture:** Angular 21 (standalone, signals, zoneless) app. Pure-signals-in-services state (no NgRx). Native browser `WebSocket` behind `WsClientService` (subprotocol bearer, reconnect, ND-40 replay buffer, claim FSM). `xterm.js` terminal viewport consumes raw binary PTY output verbatim. Three eager routes (`/pair`, `/`, `/sessions/:id`) behind a single `pairStatus` guard. Wire shapes imported from `@relay/protocol`; **no server changes** (NFR-5).

**Tech Stack:** Angular `^21`, `@angular/pwa` (`^21`), `@xterm/xterm@^6` + `@xterm/addon-fit@^0.11`, Tailwind v4 (placeholder config only), `@relay/protocol` (workspace dep), Vitest (Angular 21 default runner), pnpm workspace.

## Global Constraints

Every task's requirements implicitly include this section. Values are copied verbatim from the L0–L6 spec.

- **Package:** `@relay/pwa` at `packages/pwa/`. `private: true`, `type: module`.
- **Framework pin:** Angular `^21` (resolves to 21.2.x). Standalone-by-default, signals, **zoneless change detection** (no Zone.js), Vitest runner — app-shell §1, §2. Angular 22.0.5 IS released; it is the **sanctioned fast-follow** per app-shell §7 (revisit once signal-forms + libs stabilise), **not this build**. Do not pull v22.
- **Terminal substrate:** `xterm.js` via the scoped packages `@xterm/xterm@^6` + `@xterm/addon-fit@^0.11` (the modern rename of `xterm`/`xterm-addon-fit`) — D-18, foundations D-18 substrate.
- **Wire shapes:** import all REST/WS types + Zod schemas from `@relay/protocol` (workspace dep, pnpm symlink — app-shell §6.2). **Never fork or re-declare a schema.** Parse every server text frame with `ServerFrameSchema`; build client frames as typed `ClientFrame` objects.
- **`src/` org:** layer-first — `src/app/components/`, `src/app/services/`, `src/app/guards/`. Feature identity lives in the **filename** (e.g. `components/live-session.component.ts`, `services/ws-client.service.ts`) — app-shell §6.1. Relative imports within the package; no internal path aliases.
- **Routing:** eager-loaded routes (`loadComponent` splits are forbidden) — app-shell §4.4. Single `pairStatus` guard on every route except `/pair` — app-shell §4.5.
- **WS auth:** `new WebSocket(url, ['relay.bearer', token])` — ND-36. Never a header, never the URL.
- **API base (ND-47):** REST + WS base URL is sourced from D-13's pair-link `url=` param, persisted in `localStorage` under `relay.serverUrl` next to the bearer, with a `location.origin` fallback when absent. Do **not** hard-wire same-origin. WS swaps scheme `https→wss` / `http→ws`. Cite ND-47.
- **Bearer storage:** `localStorage`, read at boot, written on pair, cleared on unpair / `401` / WS auth reject — L3 §2. Server URL (ND-47) is stored/cleared in lockstep.
- **Output path is hot:** binary PTY frames go straight to xterm as bytes, **no base64 decode on output** (base64 is input-only, per ws-protocol §1). No stream library between socket and signal (native WebSocket) — L6 §1.
- **Styling:** Tailwind v4 as the consumption mechanism, **empty placeholder config only** — do NOT author tokens, palettes, type ramps, or component primitives the L1 delivery will prescribe (foundations §4). Structural utilities (flex/grid/spacing) are fine; committed color/type schemes are not. xterm uses its library default theme until L1 delivery swaps it. The swap must be a **config swap**, not a component rewrite (foundations §5).
- **Server couplings (NFR-5 — no server changes here):**
  - **ND-41 (scratch FR-9 / create-project FR-10):** DEFERRED — server pass owns create-by-path. Ship a stub that surfaces the deferral, cite ND-41.
  - **ND-44 (file viewer FR-13):** DEFERRED to a fast-follow — no server file surface exists. Cite ND-44.
  - **ND-42 (control-rail claim/release):** STOPGAP — client sends the control byte then an **explicit `release`** frame (works on today's wire). Cite ND-42.
  - **ND-43 (running/idle status):** STOPGAP — **client-derive** status from `updatedAt` / `totalBytes` (no server status field). Cite ND-43. **Verify first (ND-13):** confirm the byte-accounting cadence bumps `updatedAt` finely enough to distinguish running/idle across a poll interval; if not, derive from `totalBytes` deltas across polls instead.
  - **ND-48 (rail arrow keys):** OPEN — ship normal cursor-mode sequences (`ESC[A`/`ESC[B`) as the stopgap; DECCKM application-mode handling is unresolved, verify on the device pass. Cite ND-48.
- **Reconnect (L3 §3.2):** immediate retry → exponential backoff base 1 s, 30 s cap, ±20% jitter, **10-minute** continuous-reconnect window then stop + manual retry; successful `open` resets window + counter; `window.online` cancels pending backoff and reconnects immediately; idempotent state machine.
- **Latency budget (L6 §1):** ≤ 150 ms perceived input→echo on LAN/Tailscale — a budget to **verify on the real path**, not a constant.
- **Code comments:** any non-obvious behavior cites its `D-NN`/`ND-NN` per CLAUDE.md. If the build forces a new decision, file it via `decision-log` **before** writing the citation.

```ts
// auth.service.ts
import { Injectable, computed, signal } from '@angular/core';

const BEARER_KEY = 'relay.bearer';
const SERVER_URL_KEY = 'relay.serverUrl';

export interface PairPayload { token: string; url: string | null; }

@Injectable({ providedIn: 'root' })
export class AuthService {
  // Per L3 §2 + ND-47: bearer + server URL live in localStorage; read at boot,
  // cleared on unpair / 401.
  private readonly _bearer = signal<string | null>(localStorage.getItem(BEARER_KEY));
  private readonly _serverUrl = signal<string | null>(localStorage.getItem(SERVER_URL_KEY));
  readonly bearer = this._bearer.asReadonly();
  readonly serverUrl = this._serverUrl.asReadonly(); // ND-47: null ⇒ same-origin fallback
  // Per app-shell §4.5: pairStatus gates routing. 'pairing' is set by the pair
  // component mid-exchange; steady states are derived from bearer presence.
  private readonly _pairing = signal(false);
  readonly pairStatus = computed<'unpaired' | 'pairing' | 'paired'>(() =>
    this._bearer() ? 'paired' : this._pairing() ? 'pairing' : 'unpaired',
  );

  // Per D-13 + ND-47: the token AND the server url ride IN the pairing artifact
  // (relay://pair?url=<server>&token=<bearer> or its QR encoding). `url` is
  // optional (same-origin deployments omit it); a payload without a token is
  // not a valid pair link.
  parsePairPayload(raw: string): PairPayload | null {
    try {
      const link = new URL(raw.trim());
      const token = link.searchParams.get('token');
      if (!token) return null;
      const url = link.searchParams.get('url');
      return { token, url: url && url.length ? url : null };
    } catch {
      return null; // not a URL
    }
  }

  setPaired(p: PairPayload): void {
    localStorage.setItem(BEARER_KEY, p.token);
    if (p.url) localStorage.setItem(SERVER_URL_KEY, p.url);
    else localStorage.removeItem(SERVER_URL_KEY);
    this._pairing.set(false);
    this._serverUrl.set(p.url);
    this._bearer.set(p.token);
  }

  clear(): void {
    localStorage.removeItem(BEARER_KEY);
    localStorage.removeItem(SERVER_URL_KEY);
    this._pairing.set(false);
    this._serverUrl.set(null);
    this._bearer.set(null);
  }
}
```

1. **Subprotocol auth (ND-36).** `attach` opens `new WebSocket('<origin ws>/sessions/:id/stream', ['relay.bearer', token])`. Assert the factory is called with exactly `['relay.bearer', token]`. Never a header, never a query param.
2. **Frame dispatch.** Text frames → `ServerFrameSchema.parse(JSON.parse(data))`; switch on `.type`:
   - `hello` → set `hello` signal, `connectionState='attached'`.
   - `replay_start`/`replay_end` → bracket markers (no viewport obligation beyond the ND-40 drain; a "resumed" marker is optional per D-G3).

   - `claim_ack` (echo id) → `claimState='claimed-local'`, `claimExpiresAt=expiresAt`.

   - `claim_released` → `claimState='released'`, clear `claimExpiresAt`.

   - `auth_expired` → `AuthService.clear()`; expect close 4401.
   - `error` (`fatal:false`) → continue; set `lastError` **only for user-actionable codes**. Benign/no-op codes never reach the banner: `release_without_claim` (idempotent no-op — ws-protocol §2.2) is ignored; `send_without_claim` is handled by the FSM (a server-side release raced our send → drop `pendingInput`, §5.1), not shown as an error. `(fatal:true)` → close path + set `lastError`.
3. **ND-40 replay-gap buffer (mirror `AttachClient` exactly — L3 §3.3).** On open, buffer all inbound **binary** in memory. When the consumer subscribes (viewport → PtyOutputService), drain the buffer to the consumer first, then forward live. On disconnect/detach, clear the buffer. Cite ND-40, ND-03 (upstream bound).
4. **Reconnect (L3 §3.2).** On unexpected close (not a clean `detach()`), enter `reconnecting`; schedule retry with the backoff curve (immediate, then `min(30s, 1s·2^n)` ± 20% jitter); reset attempt/window on `open`; stop after the 10-minute window and expose `disconnected — tap to reconnect` (surface as `connectionState='error'` + a flag the banner reads). `window.online` cancels the pending timer and reconnects. **Fake timers required.**
5. **Claim FSM (ws-protocol §5.1, compose path).** `sendInput` when `released`: send `claim`; buffer bytes as `pendingInput`; on `claim_ack` flush one `send{data: base64(bytes)}`. A draft with a trailing newline auto-releases server-side (ND-24) → `claim_released{delivered}` → `released`. In **raw mode**, each `sendInput` is one `send` per keystroke while the claim is held (Streaming).
6. **Control-rail — claim-aware send-then-release (ND-42 stopgap).** `sendControl(bytes)` composes correctly with ND-24 streaming and does **not** flash spurious errors (architect must-fix 1 & 2):
   - **If we already hold the claim** (`claimState()==='claimed-local'`, i.e. raw-mode streaming): just `send{base64(bytes)}` — **no** `claim`, **no** `release`. Sending a `release` here would drop the held claim mid-stream and open a contention window before the next keystroke re-claims (ND-42 explicitly flags this ND-24-composition subtlety).
   - **Else** (released — line mode): `claim` → on ack `send{base64(bytes)}` → then `release` **only if the bytes contain no newline** (`\n`/`\r`). A bare control byte (`^C`, `Esc`, arrows, Shift+Tab) is not a newline, so without the explicit release the server holds the claim to the ND-01 timeout — hence the stopgap release. But **Enter's `\r` self-releases server-side** (ND-24 delivered), so an explicit `release` after it would provoke a `release_without_claim` error frame that would needlessly flash the StatusBanner (NFR-10 regression) — skip it. Cite ND-42.
7. **resize side-channel (ND-23).** `resize(cols,rows)` sends `{type:'resize',cols,rows}` regardless of claim state; SHOULD be emitted once right after open.
